01 • Foundations

What is IaaS?

Infrastructure as a Service (IaaS) is a cloud service model that provides on-demand access to fundamental computing resources—typically virtual machines, storage, and networking—over a network. The cloud provider operates the physical infrastructure; the customer configures and manages the operating system, middleware, applications, and data.

Remember: IaaS rents you the building blocks of IT infrastructure. You gain flexibility and control, but you still have responsibility for much of the software stack and its security.
ComputeVirtual machines, CPU, RAM, GPU instances, autoscaling groups.
StorageBlock volumes, object storage, file storage, snapshots and backups.
NetworkingVirtual networks, subnets, routes, firewalls/security groups, load balancers, IP addresses.

Learning objectives

  • Define IaaS and distinguish it from PaaS and SaaS.
  • Explain virtualization, virtual machines, networking, and storage in a cloud architecture.
  • Understand the shared-responsibility model and common security controls.
  • Estimate basic compute costs and identify scaling strategies.
  • Answer exam-style and technical interview questions about IaaS.

Prerequisites

Basic familiarity with operating systems, IP networking, storage, servers, and the client–server model is helpful.

03 • Operation

How IaaS works, step by step

  1. Choose a region and network. Select a location, create or select a virtual network, and define subnets and routing.
  2. Provision compute and storage. Select a VM image and size, attach storage, and define network interfaces.
  3. Apply identity and security controls. Grant least-privilege permissions, configure firewall rules, encryption, and secure administrative access.
  4. Configure the operating system and workload. Patch the OS, install runtime dependencies, deploy the application, and store secrets securely.
  5. Observe and scale. Monitor metrics/logs, set alerts, and use vertical scaling (bigger VM) or horizontal scaling (more instances) where suitable.
  6. Back up, recover, and optimize. Test restores, define recovery objectives, review usage, and remove idle resources.

Responsibility boundary

Usually provider-managedUsually customer-managed in IaaS
Physical data centers, physical servers, storage hardware, physical networking, and virtualization layer.Guest OS configuration and patches, identity/access policy, application code, data classification, firewall configuration, and workload backups—according to service and contract.
Important: “Cloud provider security” does not mean “the customer has no security work.” Exact responsibility varies by service, configuration, and provider. Confirm the responsibility matrix for the selected product.

DC-like and network behaviour

IaaS VMs behave like networked computers, but virtual network isolation, software-defined routing, security policies, and provider abstractions replace many physical configuration tasks. A VM can be stopped, resized, recreated from an image, or placed behind a load balancer, depending on the platform.

Benefits and trade-offs

Advantages
  • Rapid provisioning and flexible capacity.
  • Lower upfront hardware investment.
  • Choice of OS, software, and architecture.
  • Automation through APIs and Infrastructure as Code.
  • Global regions and managed resilience options.
Limitations / risks
  • Costs can grow through idle or oversized resources.
  • Customer must patch and secure guest systems.
  • Provider outages and quotas can affect workloads.
  • Migration and provider-specific designs can create lock-in.
  • Networking and permissions can be misconfigured.
05 • Worked examples

Solved numerical examples

Example 1 — Monthly VM cost

Question: A VM costs ₹6 per hour and runs for 120 hours in a month. Estimate the compute charge, ignoring tax, storage, network transfer, and discounts.

Given: Rate = ₹6/hour; usage = 120 hours. Required: compute cost.

Cost = hourly rate × billable hours

Substitute: ₹6/hour × 120 hours = ₹720.

Interpretation: This is only the compute estimate. Actual invoices may include disks, snapshots, public IPs, data transfer, support, taxes, and different billing rules.

Example 2 — Storage capacity

Question: An application stores 250 GB of logs per day. Estimate raw storage for 14 days, before replication, compression, and overhead.

Required raw capacity = daily data × retention days

250 GB/day × 14 days = 3,500 GB ≈ 3.5 TB using decimal units.

Engineering interpretation: Add headroom and account for retention, indexes, replicas, backups, and whether the storage service bills in decimal GB or another unit.

Example 3 — GATE-style availability calculation

Question: A service has two independent VM instances, each with availability 0.99. A load balancer routes traffic to either healthy instance, and the service is unavailable only when both VMs are down. Ignore load-balancer and network failures. Find service availability.

P(both down) = (1 − A)²
Service availability = 1 − P(both down)

Each VM unavailability = 1 − 0.99 = 0.01. Both down = 0.01 × 0.01 = 0.0001. Availability = 1 − 0.0001 = 0.9999 = 99.99%.

Assumption: failures are independent. Shared dependencies, correlated failures, bad deployments, the load balancer, and network paths can reduce real availability.

Quick cost-estimation checklist

  • Compute: instance type × billed duration × applicable rate.
  • Storage: provisioned or consumed capacity × storage rate.
  • Data transfer: outbound/inbound transfer rules and destination.
  • Extras: snapshots, load balancers, IP addresses, monitoring, support, taxes.
  • Discounts: committed-use plans or spot/preemptible capacity, if appropriate.
06 • Exam preparation

GATE-style practice set

These are original practice questions, not claimed to be previous-year GATE questions. Expand each answer to check the reasoning.

Easy 1. Which resource is most characteristic of IaaS?
A configurable virtual machine with user-managed guest OS. IaaS provides infrastructure building blocks rather than a complete end-user application.
Easy 2. In a typical IaaS model, who patches the guest operating system?
The customer is typically responsible for guest OS patching. The provider maintains the physical platform and virtualization layer, subject to the specific service boundary.
Moderate 3. A VM costs ₹8/hour and runs 50 hours. Compute cost?
₹8 × 50 = ₹400, excluding other billable resources and taxes.
Moderate 4. Two independent servers each have 0.9 availability and either can serve requests. What is combined availability?
1 − (1 − 0.9)² = 1 − 0.01 = 0.99 or 99%, assuming no shared failure point.
Easy 5. Which model generally gives the customer the most control over the guest OS: IaaS, PaaS, or SaaS?
IaaS. The customer usually configures and maintains the guest OS. PaaS and SaaS abstract more of the stack.
Moderate 6. What is the primary purpose of a security group or virtual firewall?
To control allowed network traffic to or from associated resources using rules. It does not replace identity management, patching, or application security.
Moderate 7. An application needs to handle rising request volume by adding more VM instances. Which scaling approach is this?
Horizontal scaling (scale out). Vertical scaling means increasing resources on an existing instance.
Difficult 8. A VM is highly available, but its only attached disk is not backed up. What is the key risk?
Availability of compute does not guarantee data recoverability. Disk failure, accidental deletion, corruption, or ransomware may cause data loss. Use appropriate backups/snapshots and test restoration.
Moderate 9. Which statement about pay-as-you-go is most accurate?
Charges depend on metered use and provider-specific billing rules. It does not mean every resource is free when idle; provisioned storage and reserved resources may still incur charges.
Difficult 10. Why place application instances in multiple availability zones?
To reduce dependence on a single isolated location and improve resilience to zone-level failures. The application must be designed for multi-zone operation, and shared dependencies still matter.

07 • Industry readiness

Core cloud / DevOps interview questions

1. Explain IaaS in your own words.
IaaS delivers configurable compute, storage, and networking on demand. The provider manages the physical platform; the customer typically manages the guest OS, workload, data, and access configuration.
2. What is the difference between a VM and a container?
A VM virtualizes hardware and normally runs its own guest OS kernel. Containers isolate processes while sharing the host kernel, so they are often lighter-weight, but have different isolation and compatibility characteristics.
3. What is a virtual private cloud or virtual network?
A logically isolated network space where users configure IP ranges, subnets, routes, gateways, and traffic controls. Exact feature names differ by provider.
4. How would you secure a newly created VM?
Use least-privilege IAM, restrict inbound ports, avoid public administrative access where possible, patch the OS, use SSH keys or managed access, encrypt disks, store secrets securely, enable logs/monitoring, and maintain tested backups.
5. Vertical vs horizontal scaling?
Vertical scaling changes the size of one machine (more CPU/RAM). Horizontal scaling adds or removes instances. Horizontal scaling can improve resilience but requires suitable load distribution and application design.
6. What are regions and availability zones?
A region is a geographic area containing cloud infrastructure; availability zones are separated locations within a region intended to reduce shared failure risk. Check the provider’s definitions and service availability.
7. A VM cannot reach the internet. What do you troubleshoot?
Check subnet route tables, internet/NAT gateway setup, public IP requirements, firewall/security-group rules, network ACLs if applicable, DNS, OS firewall, proxy settings, and whether the application itself is listening on the expected interface.
8. How do you avoid unexpected cloud bills?
Tag resources, set budgets and alerts, right-size instances, shut down unused environments, review storage snapshots and data transfer, use autoscaling, and inspect billing reports regularly. Budgets often alert rather than automatically stop usage.
9. What is Infrastructure as Code (IaC), and why use it?
IaC defines infrastructure in version-controlled declarative or imperative files. It supports repeatability, review, automation, drift detection, and consistent environments. Protect state files and secrets.
10. How would you design a resilient basic web application on IaaS?
Use a load balancer, multiple application instances across zones, health checks, private subnets for internal tiers, least-privilege network rules, managed or replicated data services as appropriate, backups, monitoring, and tested recovery procedures. Remove single points of failure where the requirements justify the cost.
Industry perspective: IaaS skills are useful for cloud engineering, DevOps, platform engineering, SRE, system administration, cloud security, and infrastructure support. Employers often look for practical evidence: deploying a VM, securing its network, automating setup, monitoring health, and documenting recovery.

09 • Rapid revision

Formula sheet and high-priority notes

Useful formulas

Compute estimate = hourly rate × billable hoursRaw storage = data generated per unit time × retention durationSeries availability (all components required) = A₁ × A₂ × … × AₙParallel availability (either independent path works) = 1 − (1 − A₁)(1 − A₂)…(1 − Aₙ)

Availability formulas assume the stated components and failure relationships are correctly modeled. Real systems may have dependencies, correlated failures, maintenance windows, and imperfect failover.

High-priority concepts

  • IaaS provides virtualized compute, storage, and networking.
  • Customer typically manages the guest OS and applications; provider manages physical infrastructure.
  • Vertical scaling = scale up; horizontal scaling = scale out.
  • High availability is not the same as backup or disaster recovery.
  • Least privilege, secure defaults, patching, encryption, logging, and tested recovery are essential.
  • Cloud billing includes more than VM runtime: storage, network transfer, snapshots, load balancing, and other services may be charged.
  • Use Infrastructure as Code and tags to improve repeatability and cost visibility.

Common misconceptions and troubleshooting

Misconception / symptomCorrection / first checks
“The provider secures everything.”Review shared responsibility; secure identities, OS, apps, data, and configured network controls.
VM is reachable only from inside the network.Check routing, public/private addressing, gateway/NAT design, firewall rules, and service binding.
Two VMs guarantee 99.99% uptime.Only under simplifying assumptions. Check correlated failures, load balancer, network, data layer, and failover testing.
Stopped VM means no charges.Compute billing may stop, but disks, reserved resources, snapshots, IPs, and other services may continue to incur charges.
Snapshots replace a backup strategy.Understand snapshot consistency, retention, access separation, recovery point, and restore testing.
